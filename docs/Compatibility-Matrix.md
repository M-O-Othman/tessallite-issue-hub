# Tessallite Issue Hub — Compatibility & Parity Matrix

This document is the official **Compatibility & Parity Matrix** showing every core system feature, its REST API endpoint, CLI command syntax, and corresponding Web UI visual controls. This confirms that **100% complete, flawless feature-parity** has been established across all three product surfaces:

---

| Feature / Capability | REST API Endpoint | CLI Command Syntax | Web UI Visual Components & Controls | Parity Status |
| :--- | :--- | :--- | :--- | :---: |
| **Create Complete Issue** | `POST /api/v1/issues` <br>*(Normal mode)* | `issue create --title "..." --severity HIGH --description "..."` | **Page:** `/issues/create`<br>**Controls:** Form text inputs for `Title` & `Area`, textarea for `Description`, select dropdowns for `Severity`, `Priority`, `Effort`, `Domain`, & `Category`, and **"Create Issue"** button. | **PASS** |
| **Reserve Issue ID** | `POST /api/v1/issues` <br>*(with `"reserve": true`)* | `issue create --reserve` | **Page:** `/issues/create`<br>**Controls:** **"Reserve Issue ID Mode"** sliding toggle switch (which hides/disables description and severity textareas) and **"Create Issue"** button. | **PASS** |
| **Complete Reservation** | `POST /api/v1/issues` <br>*(with `"id": "Bug-N"`)* | `issue update Bug-N --set severity=HIGH --description "..."` | **Page:** `/issues/Bug-N`<br>**Controls:** When status is `RESERVED`, a green-bordered **"Complete Description (Required to Open)"** textarea appears dynamically inside the sidebar form, forcing completion before saving. | **PASS** |
| **Overwrite Description** | `PATCH /api/v1/issues/{id}` <br>*(with `set.description`)* | `issue update Bug-N --description "..."` <br>*(or `--description-file path`)* | **Page:** `/issues/{id}`<br>**Controls:** **"Edit Full Description"** link that expands a collapsible form with a full-width textarea and a **"Save Description"** button (isolated from other fields). | **PASS** |
| **Append Comment / Note** | `PATCH /api/v1/issues/{id}` <br>*(with `append_description`)* | `issue update Bug-N --append-file file.md` | **Page:** `/issues/{id}`<br>**Controls:** **"Append Discussion / Note"** card with a monospace-font textarea and a dark **"Append Comment"** action button. | **PASS** |
| **Edit AKA Aliases** | `PATCH /api/v1/issues/{id}` <br>*(with `set.aka`)* | `issue update Bug-N --set aka=XMLA-123` | **Page:** `/issues/{id}`<br>**Controls:** **"AKA Aliases (e.g. XMLA-9627)"** text input field inside the metadata sidebar form and **"Save Changes"** button. | **PASS** |
| **Edit Metadata Fields** <br>*(Project, Repo, Branch, Area, Owner, Refs, Source, etc.)* | `PATCH /api/v1/issues/{id}` <br>*(with `set.<field_name>`)* | `issue update Bug-N --set project=X --set owner=Y` | **Page:** `/issues/{id}`<br>**Controls:** **"Update Metadata"** panel on the right with individual text inputs and select dropdowns for all metadata, and **"Save Changes"** button. | **PASS** |
| **Explicit Field-Clearing** | `PATCH /api/v1/issues/{id}` <br>*(with `set.<field>=""` or `"null"`)* | `issue update Bug-N --set owner=""` | **Page:** `/issues/{id}`<br>**Controls:** Entering an empty string `""` or typing `"null"` / `"none"` inside any sidebar text input field and clicking **"Save Changes"** maps the field to `None` on the server. | **PASS** |
| **Add / Subtract Tags** | `PATCH /api/v1/issues/{id}` <br>*(with `set.add_tags` or `set.remove_tags`)* | `issue update Bug-N --add-tag tag1` <br> `issue update Bug-N --remove-tag tag1` | **Page:** `/issues/{id}`<br>**Controls:** **"Tags (Comma-separated)"** text input field. To add a tag, append it (e.g. `, tag3`); to subtract/remove a tag, simply delete it from the text box and click **"Save Changes"**. | **PASS** |
| **Retire Issue Record** <br>*(Reason, Duplicate target, Note)* | `PATCH /api/v1/issues/{id}` <br>*(with `retire` object)* | `issue update Bug-N --retire DUPLICATE --duplicate-of Bug-Y` | **Page:** `/issues/{id}`<br>**Controls:** Red-bordered **"Retire Record"** card. Select dropdown for `Retirement Reason`. Choosing `DUPLICATE` runs JS `toggleDuplicateField()` to slide open the `Duplicate of (Issue ID)` text field. Area textarea for `Retirement Note` and a red **"Retire Record"** action button. | **PASS** |
| **Wide Search & Filters** <br>*(OR search across all fields)* | `GET /api/v1/issues` <br>*(with `q`, `status`, `severity`, etc.)* | `issue find "search term" --status OPEN` | **Page:** `/` *(Ledger Page)*<br>**Controls:** Top-bar full-width search input card, interactive colored status filtering cards, and select dropdown filter blocks on the sidebar. | **PASS** |
| **Audit Trails & Mutation History** | `GET /api/v1/issues/{id}/history` | `issue find Bug-N --history` | **Page:** `/issues/{id}`<br>**Controls:** **"Mutation History"** vertical timeline cards. Each log displays the operation type badge and timestamp. Updates/Appends display a **"View Snapshot Delta"** link which slides open side-by-side JSON diff codeboxes. | **PASS** |
| **Key Template Config** | `PATCH /api/v1/config/settings` <br>*(with `issue_key_template`)* | *(Exposed via `/settings` API updates)* | **Page:** `/settings`<br>**Controls:** **"Identity Key Template"** card on the right, with a text input field pre-filled with the current template, and an **"Update Template"** button (validates final segment is `{number}`). | **PASS** |
| **Database-backed settings** | `GET /api/v1/config/settings` | *(Managed via central server config)* | **Page:** `/settings`<br>**Controls:** Left-column accordion blocks showing active **"Lookup Vocabularies"** lists, and right-column database configuration stats dashboard. | **PASS** |
