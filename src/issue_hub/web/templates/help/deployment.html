5. Single Container Deployment

The Issue Hub features a highly optimized, standalone **Single Container Deployment Architecture** that packs both the database and the web service into a single isolated context.

A. Merged Container Layout

To eliminate latency, complex network meshes, and multi-container overhead, the stack is unified into a standalone Debian-based container (derived from python:3.12-slim) that runs both PostgreSQL 17 and FastAPI simultaneously inside the same container environment.

B. Autonomous Entrypoint Script (`entrypoint.sh`)

The container's execution flow is directed entirely through a shell entrypoint script that handles full service initialization on container boot:

  1. **Directories & Permissions:** Creates required log directories and sets permissions for the postgres system role.
  2. **Enforced UTF-8 Cluster:** Scans the data volume, and if empty, runs initdb with explicit --encoding=UTF8 parameters, preventing string parsing errors on SQLAlchemy database connections.
  3. **Database Bootstrap:** Starts PostgreSQL in the background, waits for it to become ready, creates the database roles and schema if missing, and grants owner permissions.
  4. **Automatic Migrations:** Automatically executes Alembic upgrades (alembic upgrade head) to ensure the tables are fully up-to-date and seeded on every container start.
  5. **Application Server:** Starts uvicorn in the foreground on port 8080.
C. Docker Compose and Environment

Deploying the stack is as simple as launching compose. The configuration uses standard volumes to store data persistently:

services:
  app:
    build: .
    container_name: issue-hub-app
    ports:
      - "8080:8080" # Web UI & API
      - "5432:5432" # Published DB Port
    volumes:
      - pgdata:/var/lib/postgresql/data
      - .:/app

Data volume pgdata maps database cluster files outside the container, ensuring that all 3,500+ records are kept fully durable across restarts, container rebuilds, and system sweeps.
